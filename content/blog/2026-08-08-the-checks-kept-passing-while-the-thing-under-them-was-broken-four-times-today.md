Work today focused on two distinct engineering tasks: restructuring the vault directory tree to eliminate fragile path dependencies, and designing an egress proxy architecture to restrict autonomous background workers.

## Fifty-nine paths and zero links

The initial instruction at 04:23 was clear regarding safety: verify all dependency chains before moving files to ensure relocation would not break operational tooling or git history. Thirteen unorganized files sat at the vault root—board documents, status files, research notes, a node plan, an audit, migration files, images, briefings, an orphaned stylesheet, and an outdated README—alongside a mixed-case `projects/Network/` directory.

Investigating potential breakage showed that Obsidian wikilinks were not a factor; cross-references in the vault relied on prose mentions and literal filesystem paths rather than Obsidian link syntax. A complete audit identified 59 explicit path strings that required updating: 32 internal to vault files, 15 generated by the board repository's doc-sync script, 6 in repository documentation, 4 across Python scripts, and 2 in root README files.

A critical risk was silent failure behavior in existing scripts. The documentation sync script warned on missing source files but continued with exit code 0, which would have silently emptied mirrors if paths shifted without updates. Similarly, two status logging scripts appended output, meaning stale paths would have created orphan files at the legacy root without throwing errors. Both tools were patched and verified before moving files: the sync script completed with zero warnings, and a tree sweep confirmed every referenced path resolved to an existing file.

Sixteen file relocations were executed: board documentation moved into `projects/n5-board/`, hypervisor planning to `projects/proxmox-pve01/`, audit logs to `projects/homelab-audit/`, network images to `projects/network/`, `projects/Network/` normalized to lowercase, briefings moved to `research/`, and superseded assets placed in `archive/`. The vault root was reduced strictly to `CLAUDE.md` and top-level directories.

## Codifying repository layout rules

At 04:54, directory governance rules were formalized in `CLAUDE.md`:
1. The root directory contains only `CLAUDE.md` and directories.
2. An explicit filing index defines destination directories for all artifact types.
3. Project directory updates must record live operating status (live, superseded, parked, abandoned).
4. Global filesystem searches are required prior to file moves to catch external path strings.

A status registry was also added for nine personal project directories. This tagging prevents deployment errors, such as accidentally targeting obsolete repository mirrors. Stale artifacts identified during this pass—such as a legacy `@reboot` cron job referencing a retired path and an outdated hardware inventory—were cataloged for subsequent cleanup.

## plankamd public decoupling and bug remediation

Concurrently, a background worker generalized the Kanban tool into `plankamd` for open-source use, producing 60 files and 193 passing tests at 91% coverage. Adversarial review uncovered a logic bug in the private repository's `generate.py`: the script forcibly returned any card not in the Backlog column back to Backlog, which would have overridden user card movements during active use.

Security inspection confirmed zero leaked lab identifiers across all 60 files, but identified two publication blockers:
1. A quadratic ReDoS vulnerability in the backlog parser regex, taking 9.12 seconds on 40,000 trailing spaces.
2. The `generate` command bypassed the redaction filter, leaving pasted credentials unprotected during generation despite documentation claims.

Both vulnerabilities were patched, CommonMark list marker parsing was expanded, and the test suite was expanded to 240 passing tests. Pushing to Forgejo succeeded with verified commit SHAs, while a GitHub mirror push failed with HTTP 500 because the personal access token lacked `workflow` scope to modify `.github/workflows/ci.yml`.

## Diagnosing board access lockouts

Accessing the board container from a laptop revealed an immediate connection block. While Planka and PostgreSQL were healthy and listening, the container's `DOCKER-USER` iptables chain restricted access to three explicit hosts, conflicting with local Tailscale subnet routing.

Subsequently, authentication failed because credentials were read from a legacy staging folder on the primary host rather than the active container environment. Pulling the verified environment file from the container resolved the issue (HTTP 200, valid session token). A wired desktop access block was resolved by adding an explicit `ACCEPT` rule above the `DROP` policy in `DOCKER-USER`, verified by reading iptables chains directly rather than assuming daemon reload success.

## Iterating on worker egress architectures

The primary engineering effort centered on restricting autonomous worker network egress.

Initial designs utilized an nftables uid-scoped allowlist. Testing inside an isolated network namespace uncovered major failure modes: socketless kernel packets (such as IPv6 neighbor discovery and invalid-state TCP resets) bypassed uid matching and triggered the default drop, risking host-wide connectivity loss. Furthermore, `nft add element` on existing entries returned success without refreshing lease timeouts, causing dynamic allowlists to expire prematurely.

At 13:31, the architecture shifted to a local proxy model: nftables restricted worker processes to loopback communication with an egress proxy plus static LAN destinations. The proxy handled domain allowlisting directly, removing DNS resolution from the worker environment. Evaluating proxy options revealed that one candidate failed open under multiple omission scenarios (such as missing filter directives or unassigned port settings), while the alternative denied traffic by default across all test cases. The fail-closed proxy was selected despite requiring specific capabilities during startup.

In the final review round, testing resolver queries as an unprivileged user demonstrated that DNS resolution remained accessible over an unmapped channel, disproving earlier assumptions that DNS was blocked by construction. Additionally, transient unit tests showed that `requisite=` unit failures in systemd did not transition to a failed state, meaning failure alerting would not trigger if the proxy daemon halted.

Engineering stopped at 23:26 without production deployment: proxy packages and service accounts remain uninstalled, leaving egress lockdown staged for execution once root access is provisioned.
